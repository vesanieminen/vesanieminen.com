No. 01

Triggers, actions & composable JS

Internal foundation for binding client-side events to client-side actions, plus the first public consumer: Clipboard write.

F1

Trigger / action framework

Internal

A new server-side API for binding client-side triggers (DOM events, signal changes, observers, timers) to client-side actions, where each action runs inside the browser without a server round-trip unless it explicitly reports back. The whole framework lives in com.vaadin.flow.component.trigger.internal and is kept package-internal while the surface matures.

Sealed types: Trigger, Action, Argument<T>. Abstract bases: AbstractTrigger, AbstractAction, AbstractArgument, AbstractCallbackAction. Built-ins include DomEventTrigger, ClickTrigger, PropertyInput, LiteralInput, HandlerInput, SetPropertyAction, PromiseAction. Client side: per-host JSON snapshot installed via Element.executeJs + beforeClientResponse coalescing, plus a window.Vaadin.Flow.triggers registry on flow-client/src/main/frontend/Triggers.ts for add-ons to plug in factories.

PR#24361
F2

Clipboard API — write text & HTML

New API

First public consumer of the trigger framework. Entry point Clipboard.onClick(component) returns a ClipboardBinding exposing writeText(String), writeText(String, JsBuilder), writeText(C source) (HasValue source), writeHtml(...), and write(ClipboardContent) — where ClipboardContent is a fluent builder for mixed text + HTML payloads.

Actions run synchronously inside the user's click handler so the browser's user-gesture requirement for navigator.clipboard is preserved.

No. 02

Geolocation

A brand-new public package — both one-shot and continuous position tracking, plus an SPI for browserless tests.

F9

Geolocation API

New API

New public package com.vaadin.flow.component.geolocation (~13 classes). After several iterations the final shape is a static utility (Geolocation) with two flavours of usage:

  • One-shot: Geolocation.getPosition(owner, onSuccess, onError, [options])
  • Continuous: Geolocation.watchPosition(owner, [options]) returns a GeolocationWatcher with positionSignal(), activeSignal(), addPositionListener(...), and resume() / stop().

Availability hint exposed as availabilityHintSignal() returning Signal<GeolocationAvailability> (UNKNOWN / GRANTED / DENIED / PROMPT / UNAVAILABLE). Supporting types: GeolocationOptions, GeolocationPosition, GeolocationCoordinates, GeolocationResult (sealed), GeolocationError, GeolocationErrorCode, GeolocationOutcome, GeolocationPending.

Styling

One fix that resolves the long-standing non-root-context-path stylesheet problem, plus cache-busting via content hash.

F32

@StyleSheet auto-applies context://

Breaking fix

Plain @StyleSheet("foo.css") values are now normalised through a new FrontendDependencyUrlResolver.resolveToContextRoot. Bare relative paths get a context:// prefix prepended; http(s)://, //, context://, base:// pass through; /... is an absolute server path; ./... strips the leading ./. The same normalisation deduplicates spelling variants in ActiveStyleSheetTracker. Fixes broken stylesheets when the servlet is mapped at a non-root path.

PR#24235
F33

Content-hash cache busting for @Stylesheet

Behavior

Each @Stylesheet URL is rewritten with a content-hash query parameter (?v=<hash>) so browsers re-fetch on content change without manual cache busting.
