Where Things Go Wrong

Your sessions succeed at a high rate, but most friction comes from repeated CSS/styling iteration in Vaadin, stale build artifacts polluting verification, and occasional misreads of your true intent.

Vaadin theme and shadow-DOM styling churn
A large share of your buggy-code friction comes from CSS that targets the wrong theme tokens or shadow-DOM parts, forcing several rounds of trial-and-error before layouts match references. You could shortcut this by documenting the active theme (Aura vs Lumo) and its valid token names in a CLAUDE.md or task template so Claude doesn't guess.
  • CSS used Lumo --lumo-space-* tokens that resolved to nothing under the Aura theme, requiring multiple iterations to find correct token names before the layout rendered.
  • Multiple failed attempts to style shadow DOM parts before switching to @CssImport with themeFor, plus inline align-items overriding the stylesheet, delaying visual verification.
Stale build artifacts and port conflicts during verification
Verification repeatedly broke because cached CSS in target/classes or sibling dev servers squatting on the same port made Claude debug phantom problems unrelated to its actual code. You could add a clean-and-restart step (clear target/classes, pin a dedicated port) before browser verification to avoid these false signals.
  • Claude hit the wrong browser session/port (8093, 8095) and got blank screenshots from Vaadin timing, needing multiple restarts before it could confirm its own code rendered.
  • Stale cached CSS in target/classes required a resource re-copy and browser restart, sending Claude down a debugging path for code that was actually already correct.
Scope and intent misreads requiring interruption
In a few sessions Claude over-stepped or targeted the wrong object because the request's boundaries weren't explicit, forcing you to interrupt and redirect. You could state scope limits up front (e.g. 'prep only, don't solve' or naming the exact PR/worktree) to prevent wasted work.
  • Claude began dispatching sub-agents to actually solve benchmark problems when you only wanted prep scripts, requiring you to interrupt and reset its course.
  • Claude checked the wrong worktree/PR until you clarified you meant PR #32 in a separate worktree, costing a verification cycle.
